# Tokyo Nebula — Palette Refresh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refresh the five source theme palettes (`themes/*.json`) to a unified high-contrast neon family — each variant signed by one of five shared hues (violet/green/cyan/yellow/blue), with orange removed and backgrounds dropped ~5 luminance points.

**Architecture:** One task per variant (5 tasks), each TDD-driven. Per-variant changes are applied via a one-shot Node patch script that updates specific UI keys and replaces the entire `tokenColors` array with a spec-derived layout. After all 5 variants land, shared cross-variant assertions and a final family regeneration close out the work.

**Tech Stack:** Node.js (built-in test runner), VS Code theme JSON schema, the existing `zed-extension/scripts/build.mjs` resolver (unchanged).

**Spec:** `docs/superpowers/specs/2026-05-27-tokyo-nebula-palette-refresh-design.md`.

---

## File Structure

**Files modified:**
- `themes/andromeda.json` — UI palette + tokenColors refresh
- `themes/aurora.json` — same, with italic flag preserved on keyword/comment/storage
- `themes/eclipse.json` — same, cyan signature
- `themes/solstice.json` — same, yellow signature, warm bg
- `themes/polaris.json` — same, blue signature, deepest navy bg
- `zed-extension/scripts/build.test.mjs` — per-variant assertions appended
- `zed-extension/themes/tokyo-nebula.json` — regenerated by the build script

**Files NOT modified:**
- `zed-extension/scripts/build.mjs` — mapping logic is correct; only data flows through.
- `package.json`, `extension.toml`, READMEs — variant names and metadata unchanged.

**Throwaway artifacts:** Each variant task writes a one-shot patch script to `/tmp/patch-<variant>.mjs`, runs it, then deletes it. The patch scripts are NOT committed.
